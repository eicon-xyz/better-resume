# T1 证据（读转录：用户如何给智能体转向）

## 意图复述

- 我理解这票解决什么：从 DSH 会话转录里回收「用户如何给智能体转向」的真实证据，产出 `recall-report.md`，供 T3 把改进落在倒金字塔的高层（代码/架构 > 静态检查 > 书面规则 > 人工评审）；只有用户说过 ≥2 次的才算模式。
- 我怎么做，到文件粒度：用 `node /root/.dsh/tools/dsh-sessions.mjs --cwd '/root/better resume'` 解码会话到 `/tmp/dsh-retro-*/session-*.jsonl`，按记录类型过滤到 user/message 的用户原话，逐条打捞纠正/重复指令/反馈；另读跨窗口记忆 `/root/.dsh/session-memory/better resume.md`；只写 `docs/tickets/p15-agent-friendly-architecture/recall-report.md` 与本文件 `T1-EVIDENCE.md`。
- 我不做什么：不写这两个文件之外的任何路径；不改代码、文档、票据；不碰工作区未提交的 p14 改动；不编造出处、不把 AI/子代理自述当用户反馈、不把单次个案写成模式、不写重构方案、不写修改历史叙事；凭据一律打码。

## 实现决定交代

| spec 未覆盖我自行拍定的决定 | 为什么这么拍 | 我明确没做的 |
| --- | --- | --- |
| 把 `--limit` 放大到 200 解码全部会话（票只写了「dsh-sessions.mjs 解码出的 jsonl」，没写条数） | 工具默认 `--limit 4`，只覆盖最近 4 个会话，证据面不足；项目目录实际有 149 个会话目录，不放大就等于漏读 | 没读 `~/.dsh/sessions/` 之外的其他工作区会话（其他 cwd 的目录未解码）；没读 10 个没有转录文件的空会话目录 |
| 把「克隆会话」合并后再计数（27 个代表会话 / 259 条用户轮次） | 5 个会话共享同一段用户消息序列，不合并会把同一次发言数成 2～5 次，直接违反「单次观察不叫模式」 | 没改动 `~/.dsh/sessions/` 里的任何原始转录，只在 `/tmp` 里做只读提取 |
| 「次数」口径定为「人工复核后的用户轮次数」，并在报告「方法与覆盖」写明（票只要求「带次数」） | 纯关键词计数会把用户粘贴进来的智能体文字算成用户指令（如粘贴的交接文档里含 subagent 字样），必须逐条剔除假阳性 | 没把脚本正则当唯一依据；没给每条出处配可复跑命令（那是 T2 票的口径要求，T1 票未要求） |
| 侧边栏追问类记录只引用模板末尾「问题：」之后的原话 | 那一条 `user/message` 是 DSH 插件模板与用户问题拼在一起的，整条照抄会把插件文案当成用户原话 | 没把插件模板算作出处；没把 `assistant/message`、`tool/result` 当用户反馈 |
| 报告里 F19 / F20 只列 6 条可复核样本，次数（20 / 14）在「高频重复指令」给全 | 这两条命中轮次最多，逐条列进 `出处：` 会让单行过长且不增加可复核性；次数与样本口径已在「方法与覆盖」写明 | 没有为凑数把只出现一次的观察升成模式（单次观察一律进「个案」） |
| 明文凭据用 `<已打码>` 占位，并在「未覆盖」注明原始值仍在转录里 | 票要求凭据一律打码，但同时要保留「用户确实粘了凭据」这个事实与轮次 | 没对 `~/.dsh/sessions/` 做任何清理或轮换动作；没读也不能读原始值以外的推断 |
