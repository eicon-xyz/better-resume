# T2 证据（解剖历史提交：智能体最常踩的坑）

## 意图复述

- 我理解这票解决什么：用 correct 的「同类错误 ≥2 次才成类 + 修复取能消灭它的最高层」与 architect 的设计红旗，解剖 `git log` 全部已提交历史（至 HEAD `b09bbd2`），把智能体重复犯的错误类按证据条数降序排出，产出 `pitfalls-report.md`，供 T3 在重架构里按层落改进。
- 我怎么做，到文件粒度：证据源是 `docs/**/PROBLEMS.md` 各阶段问题台账（每条对应一次真实提交）与提交自身的 diff；每条坑给出 sha + 文件:行号 + 摘录，行号按 HEAD `b09bbd2` 的版本、台账行的 sha 取 `git blame`，频次由一条可复跑的 `git grep` / `git log --grep` 命令给出；只写 `docs/tickets/p15-agent-friendly-architecture/pitfalls-report.md` 与本文件。
- 我不做什么：不写这两个路径之外的任何文件；不动工作区未提交改动（p14 在飞）；不跑 `checkout`/`reset`/`clean`/`stash`；不把决策写成坑；不给具体重构方案；不改仓库既有文档；凭据不入报告。

## 实现决定交代

| 决定 | 理由 | 影响 |
| --- | --- | --- |
| 频次口径 = 计数命令的输出行数 = 该条 `出处` 列出的证据条数 | 票面要求「频次必须由可复跑命令得出」且「按证据条数降序」；把两者绑成同一个数就不会出现手数的频次 | 12 条频次命令已逐条复跑，`expect=got`：6/6/5/4/3/3/3/3/3/3/3/2 |
| 证据以 `docs/**/PROBLEMS.md` 台账为主源，只有在没有台账记录时才用提交本身 | 台账每条对应一次真实提交且带症状/根因/修法，比从 diff 反推更硬；同一事件若同时取提交与台账会被记两次 | P06/P08 全用提交 diff，P09 混用（2 行台账 + 1 个提交），其余 9 条全用台账行 |
| 引用台账行时 `sha` 取 `git blame`（该行引入提交），`文件:行号` 按 HEAD `b09bbd2` | 台账文件只在 HEAD 有稳定行号；blame 给出该行真正的来源提交，两者都可机械复核 | 报告开头写明口径；抽查 `git show <sha>:<path>` 与 `blame -L n,n` 一致 |
| `$L` / `$R` 两个导出变量代替在每条命令里重复 12 个路径 | 12 条命令逐条贴全路径会淹没报告，且复制粘贴更易错 | 变量定义写在 `方法与覆盖`，命令可原样复跑 |
| 只取台账里能对上提交的条目，不改写也不复核既有台账措辞 | 红线：不改仓库既有文档；P13 §17 自己就记着「自述有轻微失真」 | 那条失真记录只作为 P09 的证据之一，不当作事实陈述 |
