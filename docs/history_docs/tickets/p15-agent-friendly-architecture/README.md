# p15 让代码库对智能体友好（agent-friendly rearchitecture）

Status: implementing（提案已获用户点头；按层实施中，实施票 T4–T9 起）

## 范围

目标：让「智能体默认做对事」——错误写不出来，而不是写了再被人抓住。倒金字塔四层，投入从多到少：

1. 代码/架构改进（边界、类型、不变量）；
2. 静态检查（lint、测试、CI）；
3. 书面规则（注释、AGENTS.md、skills）——只兜前两层兜不住的；
4. 人工评审——只花在设计这个环境上。

数据基础：`recall-report.md` 的 [F01]–[F20]（用户转向模式）与 `pitfalls-report.md` 的 [P01]–[P12]（重复错误类）。
每条建议都指回这些条目；候选形态逐一过 `architect/references/design-red-flags.md` 筛查，结论在括号内。

### 第 1 层：代码与架构

建议：1 票据状态成为唯一进度源——`Status:`/`Blocked by:` 由脚本校验并输出 frontier（下一个可开工票），「提案→点头→动工」是可查状态而非口头约定，`verify.sh` 增票据结构层。[F01][F19][F20][P07]（红旗筛查：一个查询接口背后是完整状态机；状态唯一属主=票据文件，无第二副本）

建议：2 TS 侧把吞失败变成编译期错误——`@typescript-eslint/no-floating-promises` 收紧为 `ignoreVoid:false` 并启用核心 `no-void`；原型 A 实证历史形态双双变红（3 errors）。现配置经预设已开该规则，但 `void` 包装的调用恰好穿透，正是 [P01] 的 TS 实例形态。[P01][F16]（红旗筛查：收紧一处配置消灭一类，无新接口）

建议：3 Python 侧吞失败形态不靠 lint（原型 A 实证 `ruff --select ALL` 零告警），靠架构消掉：把「await 才有值」的判断改成同步值 API——配置状态是一次取回的快照，判断用值不用协程，错误用法写不出来，行为由测试兜底。[P01][P11]（红旗筛查：接口收窄——async 布尔换成同步快照，调用方少学一样东西）

建议：4 部署面与连接参数的每条隐式默认值集中成一份声明（缓存头、代理、迁移、属主、upstream 解析、WS 超时），由 `compose_smoke.sh` 与协议契约测试消费；没有断言的默认值不允许存在。[P02][P11][F11]（红旗筛查：消灭 hand-synced list，单真源）

建议：5 缓存对象自带写路径失效语义（写后读一致是对象不变量），TTL 只兜底；进程内缓存跨副本失效走写路径，「只在本地失效」的写法不存在。[P10]（红旗筛查：失效协议收进模块内部，调用方不学）

建议：6 协议语义做成契约测试套件、适配器必过：`wait()` 在 `stop()` 前不得返回、成功路径显式 `close(1000)`、连接参数无隐式默认。[P11][P01]（红旗筛查：契约测试=接口的测试面，适配器可换而语义不动）

### 第 2 层：静态检查

建议：7 每个 verify/探针脚本自带「已知坏输入必红」自检并进 `verify.sh --layer scripts`；只打印结论不判定的脚本算缺陷（D22 口径）。[P03][P09][F15]（红旗筛查：自检是脚本接口的一部分，工具与被测同权）

建议：8 派生产物漂移即红：openapi.json↔schema.d.ts、层地图、skills/api 索引全部带 `--check` 并由 `verify.sh` 聚合，本地与 CI 同一条命令。[P06][P08]（红旗筛查：一份真源多份派生，「两份必须相等」的关系不许手写）

建议：9 引证与数字机械核对：`docs/tickets/**` 与验收包里的 `文件:行号` 用解析器在 HEAD 复核（短名按唯一 basename 解析——原型 C 实证 52/52 可判），数字只能来自贴出的命令输出块。[P09][F15][F16]（红旗筛查：解析器是一个深模块——一个 check 接口吃任意报告）

建议：10 历史叙事门禁进 `verify.sh`：禁词集用收窄模式，排除围栏代码块与显式豁免标记（原型 B 实证：对真实历史文档变红；现文档仅 AGENTS.md 规则原文 3 处引用需豁免）。[F06][P05]（红旗筛查：豁免必须显式点行，不做模糊排除）

建议：11 测试 hermetic：CI 以清理过的环境跑测试（代理/PATH/本机文件不构成隐式入参），测试内禁止真实 sleep 轮询、统一走注入时钟的有界等待原语，跨进程共享状态由 fixture 还原。[P04][P07][P12]（红旗筛查：等待原语一个实现多处受益）

### 第 3 层：书面规则（最小化）

建议：12 执行=派子代理、验收=机械核对写进票据模板（五栏交接包必填、写入路径越界即红、sha256 基线自动比对），难题即时入 PROBLEMS；提交与推送永远是用户逐次授权的显式动作，工具只检查「未授权不动远端」。[F03][F02][F13][P07]（红旗筛查：模板与脚本各一份，规则文件只放指针）

建议：13 远端与交接状态可读化：PR/base/合并状态由 gh 只读命令取回，HANDOFF 与会话断点是生成物（带 `--check`），模型路由是配置不是口头约定。[F05][F12][F18]（红旗筛查：只读接口，权限不放大）

建议：14 书面层只留兜不住的三件事：用 create-verification-skill 产出「交付验证技能」（文案判据、AI 味词表、中文、图/HTML 出口、改动说明格式），AGENTS.md 与 CODING_STANDARDS.md 只引用不复制内容。[F07][F08][F09][F10][F14][F16]（红旗筛查：技能是单一真源，杜绝两份规则各自演化）

建议：15 凭据唯一入口：key 模式扫描进 `verify.sh --layer scripts`（命中即红），`.env` 是唯一投放通道，模板只写变量名。[F04]（红旗筛查：入口唯一，绕过即红）

### 原型结论（开放问题用原型回答，未向用户提问）

探针一次性跑在系统临时目录，仓库零残留（`git status` 计数与探针前一致）：

- A（静态检查能否抓住吞失败）：TS 能——`no-floating-promises(ignoreVoid:false)` + 核心 `no-void` 对两个历史形态报 3 errors（探针含 `void props.onSubmit(x)` 与裸调用）；Python 不能——`ruff --select ALL` 对「协程当布尔用 / 未 await 赋值」零告警。结论分别落进建议 2 与建议 3。
- B（历史叙事门禁能否真判定）：能，但模式要收窄。宽松模式在现文档误命中 21 处（CODING_STANDARDS 的「不适用」模板把「本次…」当术语用）；收窄模式对真实历史文档变红，阳性样本取自 `84f622b` 删除的文字：

```text
**P1-A 浏览器手测已完成**（第 3 轮通过，2026-09-17）：…
| 第 1 轮 | 2026-09-15 | §1 步骤 1–4 …
```

现文档残余 3 处全在 AGENTS.md 硬规则原文（引用禁词做教学），用显式豁免标记处理，落进建议 10。
- C（引证能否机械核对）：能——两报告 52 条 `文件:行号` 引证中 44 条路径直配，8 条短名全部唯一命中一个文件（如 `event_map.py` → `apps/api/src/better_resume/media/event_map.py`），basename 兜底解析后 52/52 可判定，落进建议 9。
