# recall-report：用户如何给智能体转向

## 方法与覆盖

- 转录来源与读法：`node /root/.dsh/tools/dsh-sessions.mjs --cwd '/root/better resume' --limit 200`。默认 `--limit 4` 只覆盖最近 4 个会话，必须显式放大。项目会话目录 `~/.dsh/sessions/--root-better~0020resume--/` 共 149 个会话目录、153 份转录（139 份 `session.v4.jsonl.zstd` + 14 份 v3），解码出 149 条会话记录、109 989 条原始记录、1 989 条 `user/message`。
- 用户原话的提取口径：只取 `delegationDepth=0`（人开的会话）且 `data.source.kind=user` 的 `user/message`；`kind` 为 `agent-instructions` / `runtime-context` / `skill-catalog` / `time-context` / `tool-jobs` / `agent-message` / `subagent-settled` / `model-selection` 的记录是系统或智能体注入的，不算用户原话。命中 31 个顶层会话、310 条用户轮次。
- 克隆件合并：5 个会话共享同一段用户消息序列（`session-78e3b31d` / `session-2dcfaa07` / `session-7962ef9f` / `session-9b91b822` / `session-f5f2060f`），按最长者为代表合并；合并后 **27 个代表会话、259 条用户轮次**。本文所有「次数」都按合并后的轮次计，同一句发言不因会话被复制而重复计数。
- 计数口径：先按关键词筛出候选，再逐条人工核对（剔除用户粘贴进来的智能体文字与工具输出的假阳性），同一会话的克隆件只算一次；`出处：` 行列可复核样本，`## 高频重复指令` 的次数是复核后的轮次数。
- 侧边栏追问：记录把 DSH 的插件模板与用户问题拼在同一条 `user/message` 里，引用只取模板末尾「问题：」之后的原话，模板部分不计。
- 跨窗口记忆 `/root/.dsh/session-memory/better resume.md`（60 行）已读，但它本身是智能体写的窗口交接，只作覆盖参考，未作任何 `[F..]` 的出处。
- 打码：转录里出现过的 API key / APP_ID 一律写成 `<已打码>`。
- 未纳入模式但计入总数：子代理会话里以 `user` 角色出现的「五栏交接包」是主代理写的，按票不算用户反馈。
- 记录类型 `user` 之外的原始记录（`assistant/message`、`tool/result`）只用于核对上下文，不作 `[F..]` 出处。
