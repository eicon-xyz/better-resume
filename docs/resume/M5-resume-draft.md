## 1. 本阶段新增条目（有执行证据）

- **场景绑定注册中心（旧项目"最有设计感部分"的等价物）**：五个业务场景（对话 / 出题 / 答案评分 /
  追问 / 报告总结）各自一行绑定（adapter + target_ref，密钥只在环境变量），
  DB 表 + 进程内缓存 + `GET/PUT /api/v1/scenes`；切换绑定后**下一次 AI 调用即生效**，
  服务层零业务改动（diff 证据：7 行可选参数，见验收 §2）。
- **第二个 AI adapter（真接缝，非死代码）**：星云 SparkBot 工作流 adapter —— Bearer apiKey:apiSecret、
  `flow_id/uid/stream/history/parameters`、SSE 归一成与 OpenAI 路径完全相同的 `StreamEvent`、
  Pydantic 输出强校验（失败重试一次）、错误三态、注入防御与 OpenAI 路径同一道防线。
- **一套契约、两个实现**：10 条 vendor 无关契约 × 2 实现（20 例）驱动两个 adapter；
  **突变校验**证明套件有鉴别力（故意让 reasoning 混进 content → 对应用例红）。
- **拒绝"契约靠猜"**：旧项目对工作流输出做了多别名回退（`sugest`/`total_score` 之类），
  我们只做显式映射 + 必需字段强校验，并有**反例用例**锁死这条纪律。
- **双供应商对照脚本**：同一场景一次跑两个 provider（真 DeepSeek + 本地假星云），
  打印请求/解析字段/耗时对照并断言字段集合一致；错误语义一致性另有 2 例契约测试。
- **前端 `/settings/ai` 面板**：五场景表格（中文标签 + 技术名）、供应商切换、
  "未配置（缺哪个环境变量）"诚实标记、失败按统一文案口径提示。
