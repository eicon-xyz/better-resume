# 简历草稿（P1 实时语音 / 真模型容量 / 生产形态演练）

> 口径原则（沿用 M6）：**只写跑通并可复跑的东西**；未验证的如实标注。
> 对外物 = 四条命令能复现全部关键数字（见各条证据路径）。

## 1. 本阶段新增条目（有执行证据）

- **实时语音识别（边说边出字）端到端**：为转写通道新增第四个 adapter（阿里百炼 Paraformer 实时 WS）——
  懒连接（无音频不建供应商会话）、增量帧映射为 `replace/archive/final` 事件流、尾部预算（供应商拖尾
  不再挂住用户）；**端到端穿 nginx：首个增量 0.56s、松手→final 1.1s、关闭码 1000**（`v3_ws_probe --realtime`）。
  多句真机（3 句 13.1s）：20 partial + 3 archive + final 正确拼接，**含供应商整句自我纠错**的真包证据。
- **性能缺陷的根因修复**：松手后 10.1s 才出 final —— 定位到 `websockets` 的 `close_timeout` 默认 10s
  （供应商不回关闭帧），显式 1s + 2s 尾部预算双保险，**10.1s → 1.1s**；连接参数一律显式化成为工程约定。
- **真模型并发压测与限流标定**：多身份并行把真模型 SSE 推到 **24 并发流**（此前 c≤4），供应商零 429/5xx、
  首帧劣化仅 ~30%；据此把 `ai_call 6→2、answer 8→2`（红-绿测试钉住 + 标定后天花板实证 c=16→8ok+8rl
  分毫不差）。量化了"进程内限流 × N 副本 = 单身份配额 ×N"这一诚实边界（`M6-capacity.md` §2.7）。
- **Redis 生产形态演练**：新增两个可重跑的故障实验（网络分区、真从库提升接管服务名）——
  分区期间 `/healthz` 9/9 正常、认证路径 503+Retry-After（降级语义在真网络故障下成立）、自愈 0.2–2.2s；
  手动 failover **91/92 请求正常、恢复 109ms、切换前会话存活、拓扑自动还原**（恢复动作放 `finally`）。
  演练中揪出并修复真 bug：**worker 心跳写在兜底 try 外，主从切换直接 exit 1**（红→绿→真机复验）。
- **长跑稳定性**：**60 分钟浸泡 3600 请求 0 失败**；非会话 Redis 键增长 0、PG 连接 0 增长、api 内存 +0.5MB/h。
- **测试自动化收口（P2）**：`scripts/verify.sh` 单一入口（CI 与本地同一份命令），pytest 分层标记
  （unit/docker/real）+ 默认排除重型；nightly（部署面+故障）/weekly（全量+60min 浸泡）定时化；
  真机套件带**花费预算守卫**（超限/缺凭据非零退出，永不静默跳过）；14 个脚本全部有回归契约；
  七个深模块覆盖率 ≥93.2% 并以 **90% 底线**钉进 CI。**744 后端 + 161 前端全绿**。
