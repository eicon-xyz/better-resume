# 简历条目（v8：统一为"用什么技术，解决了什么问题，有数据摆数据"句式，无括号）

---

BetterResume—AI 模拟面试平台 https://github.com/eicon-xyz/better-resume
技术栈： Python FastAPI SQLAlchemy PostgreSQL Redis WebSocket SSE React Docker
项目简介： 一个集成用户鉴权、简历解析、AI 出题、语音/文字答题、评分追问与报告复盘的全链路模拟面试平台。针对"模型输出不可控""转写与总结长耗时阻塞面试"的痛点，将耗时任务全部异步化、模型调用统一收口，并以生产形态演练验证可靠性。

• 采用自研韧性中间件统一收口所有模型调用，内置超时、熔断、并发隔离和令牌桶限流，解决 AI 调用散落在业务代码里一处抖动全链雪崩的问题，24 并发流式压测无一次调用错误。

• 基于 Redis 实现分布式单飞，解决多实例部署下同一请求重复打到模型造成的计费浪费；抢锁前先查一次结果，同时堵住 owner 释放瞬间第二个实例插手重跑的缝隙，两实例并发提交同一题上游只调用一次。

• 设计 Redis 热层缓存加速面试会话恢复，解决实例宕机后中断面试无法续答的问题；针对缓存容易让用户看到过期视图的问题，采用写路径主动失效加数据来源标记兜底，Postgres 保持唯一真相源。

• 采用跨进程缓存 TTL 与写路径失效，解决多副本下修改配置只有本地实例生效、其余副本拿着旧配置持续返回 503 的问题。

• 通过把主循环内心跳写等每一次依赖调用罩进异常保护，解决后台 worker 在 Redis 主从切换、网络分区时直接退出导致任务无人处理的问题，依赖抖动后进程存活、积压任务照常消费。

• 基于 WebSocket 实现答题语音实时上行转写，并自研句池归并算法，解决流式增量包乱序和转写自我纠错导致的文本错乱问题，边说边出字，实测开口约 0.6 秒出首字、停止说话 1.1 秒拿到最终文本；转写在前端只追加去重，绝不覆盖用户手写内容。

• 采取生产形态故障演练代替方案评审验收系统容错，执行 kill 实例、网络分区、主从切换和长时间浸泡，解决高可用设计只停留在纸面的问题：面试中途 kill 掉正在服务的实例 237ms 由另一实例接管且会话状态与报告数字一致，Redis 主从切换 109ms 恢复，60 分钟浸泡 3600 请求零失败。
