# 简历草稿（M2 面试里程碑）

> D14 硬规则：每个里程碑结束更新一次简历草稿。
> 口径原则：**只写已经跑通、可演示的东西**；M2 的对外物 = 上传简历 → 完整面试 → 雷达图报告。

## 1. 本阶段新增条目（有执行证据）

- **面试引擎（亮点② 的落地形态）**：把原项目的「两层状态」重写成两套显式状态机 ——
  会话生命周期（draft→resume_uploading→ready→in_progress→finished/abandoned）与答题流程
  （init→asking→evaluating→follow_up→completed），转移表穷举测试（61 例），同状态幂等、
  非法转移显式报错；流程状态挂在 Postgres 行上并用 version 乐观锁（CAS）更新，
  **10 个并发自增全部落地**。
- **确定性简历解析（亮点⑤）**：pdfplumber 提取带字号/加粗的文本块 → 章节启发式打分
  （关键词 + 字号 + 加粗，CJK 无空格回退）→ Pydantic ResumeContext；
  **解析完全不依赖 LLM**，扫描件/坏文件给出带 code 的明确错误；真实演示中模型出的题
  直接引用了简历里的 P99 与幂等键细节（反幻觉的证据）。
- **出题 → 答题 → 评分 → 追问全链路**：结构化输出强校验（schema 不合规不留半截状态）、
  requestId 幂等门禁（唯一约束 + 回放，不重复计费）、**题级锁**下并发同题只评一次、
  评分失败回滚到可重答状态；追问裁决是**纯函数规则链**（完成短路→上限→AI 建议→低分→要点缺失），
  72 例判定表穷举 + fail-open，题号 2-F1 值对象化。
- **报告与雷达图**：结束即冻结报告快照（幂等），四维 = 准确性/深度/要点覆盖/完成度，
  由分数与缺失要点**纯聚合**得出（LLM 只写一段总结，失败不影响数字）；逐题回放含追问原因。
- **前端三段页面**：上传页（%PDF- 魔数校验 + 上传进度 + 解析预览 + 继续上次）、
  面试房间（题目流 / 追问徽章 / 反馈卡 / **双重防重复提交** / 刷新恢复）、
  报告页（**自绘 SVG 雷达**，无图表库；几何算法 11 例单测含全 0 与满分边界）。
