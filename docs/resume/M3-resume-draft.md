# 简历草稿（M3 韧性里程碑）

> D14 硬规则：每个里程碑结束更新一次简历草稿。
> 口径原则：**只写已经跑通、可演示的东西**；M3 的对外物 = 一个方法（`run(stage, key, fn)`）
> 背后藏着单飞/熔断/舱壁/超时/限流，且"并发同 key 只调一次上游"有测试与真模型双重证明。

## 1. 本阶段新增条目（有执行证据）

- **AI 韧性收成一个方法（D16 亮点① 的落地形态）**：`ResilientAiResilience.run(stage, key, fn)`
  按固定顺序串起 **进程内单飞 → 按 stage 熔断 → 舱壁 → 超时 → 上游**，失败统一归一到
  三态（timeout/overloaded/unavailable）+ 一个不可重试态（invalid）；四条 AI 链路
  （聊天流 / 出题 / 评分 / 追问+报告）**只 import 这一个方法**，签名与蓝图逐字一致。
- **流式单飞（自研，旧项目没有的部分）**：同一个 key 的并发聊天流只打开 **一条**上游流，
  单生产者 + 多消费者游标广播，**迟到订阅者从头回放**、全部消费者离开才取消上游、
  完成后的流**不回放**（避免"连问两次同一句话拿到旧答案"）；背压按最慢消费者限窗，
  消费者逐帧内容与 leader 逐字节一致。
- **熔断 / 舱壁 / 超时都跑在注入时钟上**：`ManualClock` 驱动开态等待、半开放行、
  排队预算与整体超时，**78 例韧性测试 0.08s 跑完**（无真实等待）；熔断按 stage 隔离，
  舱壁拒绝不计入熔断失败，熔断开态不占舱壁名额（装饰顺序有专门用例）。
- **限流矩阵落到中间件**：general/read/answer/heavy/ai-call 五桶令牌桶，身份 = 会话 cookie 的
  sha256（不查 Redis、不落原文），无 cookie 退化为 IP，超限 429 + `Retry-After` +
  `X-RateLimit-*` 头；限流自身出错一律 fail-open（限流不是正确性）。
- **回放与负缓存分阶段**：聊天 0（永不回放）/ 评分·追问·报告 60s / 出题 300s；
  只负缓存 schema 类**不可重试**失败 10s —— 因此 M2 的「评分失败可回滚重答」不变量原样保留。
- **顺手修掉的 4 个跨里程碑缺陷**（详见 PROBLEMS.md P0/P8/P10）：
  ①三个 resilience key 不满足去重语义前提（换简历出题会命中旧批次、换答案复用旧追问、换模型串流）；
  ②韧性错误 kind 不在 SSE 事件的字面量里，被兜底 `except` 静默降级成 "unknown"；
  ③提交失败会清空候选人已写的回答；④`storage.py` docstring 在干净环境触发 SyntaxWarning。
