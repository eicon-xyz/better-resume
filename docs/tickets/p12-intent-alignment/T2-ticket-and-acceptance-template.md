# P12-T2 — 票据与验收包模板：意图复述 + 实现决定交代 + 改动面自查

- Status: ready-for-agent
- Blocked by: T1
- 唯一写入路径：`docs/agents/issue-tracker.md`（**只许写这一个文件**）

> 阶段：P12（意图对齐与验收减负）。依据 `README.md` §1.3 第 3、7 件事与 §1.4 Q2（用户选 (c)：只在收工时点头级介入）。
> 依赖 T1：本票要引用 `CODING_STANDARDS.md` §5 的五类高风险面，T1 未落地前不要开工。

## 目标

意图漂移发生在**票据级**：spec 没写、模型自己拍了的小决定（字段名、降级措辞、回退策略、哪个异常吞掉哪个抛出）
目前没有任何地方强制交代，用户只能在阶段末靠读代码把它们重建出来。

本票把两段**模型自述**变成模板里的必填段——它们都**不需要用户点头**：

- **开工前**写「意图复述」：给评审方一个可比对的锚（没有它，评审只能从 diff 反推意图）；
- **收工时**写「实现决定交代」：把 spec 没覆盖、模型自己拍的决定摆到台面上。

## 写入位置（精确）

在 `## 目录约定` 之后、`## 当某个技能说「发布到 issue tracker」` 之前，插入一节：

`## 票据与验收包的必填段`

既有各节**不重排、不改字**；`## 目录约定` 里「票据」与「证据」两条可以在句末加一个指向新节的指针，除此之外不动。

## 新节必须包含的五块内容

### 1. 票据文件：`## 意图复述`（开工前填）

三行，用**自己的话**，不许抄 spec 原文：

- 我理解这一票要解决什么问题；
- 我打算怎么做（写到「改哪个文件的哪一节 / 哪个函数」的粒度）；
- 我不做什么。

用途要写明：这一段是**给评审方比对的锚**，不是给用户点头用的；用户不需要读它，但漂移时它是第一个证据。

### 2. 票据文件：`## 实现决定交代`（收工时填）

三栏表格：

| spec 未覆盖、我自行拍定的决定 | 为什么这么拍 | 我明确没做的 |
| --- | --- | --- |

规则（必须写进新节）：

- 只记 **spec 没写** 的决定。spec 写了但做偏了的，记「与提案的偏差」，**不记这里**。
- 没有就写「无」；**不许留空、不许删掉这一段**（空段本身就是信号）。
- 「我明确没做的」这一栏用来钉住范围：写下那些看起来该做、但本票故意不做的事。

### 3. 验收包：`## 自行拍定的决定`

跨票据聚合成一张表，与既有的「与提案的偏差」**并列**。必须写明两者的区别：

> 偏差 = 我偏离了 spec；自行拍定 = spec 没说、我补了。后者才是验收时最难发现的那一半。

### 4. 验收包：`## 改动面与高风险面自查`

三块内容：

- `git diff --stat` 的**原始输出**（不许只写「改了 3 个文件」）；
- **与票据头部声明的「唯一写入路径」逐条比对**：出现声明之外的路径 = **越界，直接判红**，不是「顺便说明一下」；
- 按 `CODING_STANDARDS.md` §5 的五类逐类勾：**碰了 / 没碰** + 证据指针（`文件:行号` 或命令输出）。
  「没碰」也要写，因为它是用户不用再看那一片的依据。

### 5. 票据尺寸上限

一张票据 = **一个缝、≤ 4 个用例、一个写入路径**。超过就拆票。
理由要写明：返工单位的大小由**票据尺寸**决定，不由 checkpoint 决定——票越小，「收工才交代」的代价越低。

## 适用范围（必须写进新节）

- 写进新节的适用范围**不得带阶段编号**——`AGENTS.md` 硬规则 2 明文：临时性的开发阶段划分一律不进任何文档。
  用「本节生效之后新建的票据与验收包」这类不依赖编号的表述。
- **既有票据与历史归档一律不改**：`docs/history_docs/**` 零改动，不要为了「统一格式」去回填旧票据。

## 样例（照这个粒度写）

```markdown
## 意图复述

- 要解决：降级发生时用户看不到任何提示，只能从结果反推。
- 打算怎么做：在 `interview/degraded.ts` 加一个提示条组件，由 `roomStore` 的 `degradedReasons` 驱动。
- 不做：不改后端的降级判定逻辑，也不动报告页。

## 实现决定交代

| spec 未覆盖、我自行拍定的决定 | 为什么这么拍 | 我明确没做的 |
| --- | --- | --- |
| 降级提示的中文措辞用「简历没有解析出可用的文本层」 | spec 只要求「明示降级」，没给措辞；与上传页既有提示语气一致 | 没有改解析器的失败分类，只改了展示文案 |
```

## 反例（写成这样算不合格）

- 「意图复述」抄 spec 原文（那样它就失去了作为独立锚的意义——评审要比对的是**两种表述**）。
- 把「与提案的偏差」和「自行拍定的决定」合成一栏（两者混在一起，用户就没法只看后者）。
- 用「无实质变更」「按规范执行」这类话填表。
- 高风险面自查只写「已检查，无问题」，不给证据指针。
- 改动面越界了却只写一句说明，不判红。
- 回填 `docs/tickets/p11-*` 或 `docs/history_docs/**` 里的旧票据。

- 我理解这一票要解决什么问题：票据级没有位置强制交代「spec 没写、执行方自己拍的」决定，验收时只能靠读 diff 反推意图；票据本身也没有尺寸上限来压住返工单位。

## 实现决定交代

| spec 未覆盖、我自行拍定的决定 | 为什么这么拍 | 我明确没做的 |
| --- | --- | --- |
| 把「适用范围（本节生效之后新建、旧票据与历史归档不改）」写在节首，而不是节尾 | 票据只说「必须写进新节」，未定位置；放节首能让读者在读五块之前先知道边界 | 没有把适用范围塞进每个子块重复一遍 |
| 放弃票据允许的「在「目录约定」的「票据」「证据」两条句末加指针」 | 加指针会改动既有行，而本票验收口径要求 `git diff --stat`「只有追加行」；指针是可选项，放弃它换来纯追加 | 没有为了可发现性去改动任何既有句子 |
| 高风险面自查只指回 `CODING_STANDARDS.md` §5「人工评审的高风险面」的节名，不复制五类原文 | 避免两份原文漂移；「引用而非抄录」这一约束出自派活交接包，票据正文没有该表述 | 没有枚举五类名称、没有复制 §5 的「看什么 / 出处」内容 |
| 五块用 `###` 子标题组织在同一个 `##` 节下 | 保持新节是「目录约定」与「当某个技能说…」之间的单个顶层节，不新增 `##` 打乱既有目录顺序 | 没有把五块拆成多个顶层 `##` 节 |
| 把两段自述的落点定在票据文件末尾（开工前追加「意图复述」、收工时追加「实现决定交代」） | 票据只说「开工前填 / 收工时填」，未定落点；末尾追加是纯追加，能保住 `git diff --stat`「只有追加行」的口径，也与 `docs/agents/subagents.md` §8.3 的边界一致 | 没有规定落点必须在文件头，也没有为自述另开文件 |
