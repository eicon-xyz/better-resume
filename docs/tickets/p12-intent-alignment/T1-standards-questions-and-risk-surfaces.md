## §5 必须包含的内容

五类，一类一行，三栏：类 / **看什么**（检查动作，不是要求） / 出处。

| 类 | 看什么（示例写法） | 出处 |
| --- | --- | --- |
| 权限与认证 | 这次改动有没有新增或移动端点的鉴权依赖、session 校验、WS ticket 校验的位置？ | `docs/DECISIONS.md` D11、`identity/` |
| 状态变化与幂等 | 幂等键（`request_id`）的生效范围有没有变？报告冻结、题级锁的边界有没有被绕过？ | `GLOSSARY.md`（幂等键 / 报告冻结）、`interview_engine/` |
| 并发与重试 | 供应商调用有没有绕过 `ai_resilience` 链？`--scale api=2` 下这次改的状态是进程内还是跨副本共享？ | `docs/DECISIONS.md` D19/D20、`AGENTS.md` §开发规范 |
| 数据一致性与迁移回滚 | 有没有新迁移？它能不能 downgrade？模型与迁移有没有漂移？JSONB 字段的语义有没有被复用成两种含义？ | `bash scripts/verify.sh --list` 的 contract 层（`alembic check`） |
| 对外契约与降级语义 | `openapi.json` / `schema.d.ts` 变没变（契约三件套跑没跑）？依赖不可用时是不是 503 + Retry-After？降级有没有**明示**？WS 关闭码对不对？ | `AGENTS.md` §开发规范（错误语义 / WS 转写）、`docs/DECISIONS.md` D23 |

写法要求：每行是**一个检查动作**（「有没有…」「变没变…」），不是一条规定（不写「必须走 ai_resilience 链」——那是 `AGENTS.md` 的活）。

## §6 必须包含的内容

把**不能变成自动检查**的判断类规则，改写成评审期逐条必答的问题。硬约束四条：

1. **条数 ≤ 8**；
2. 每条必须标注它**指回哪条既有规则**（文件 + 节名）——**不许发明本仓库没有的新规则**；
3. 每条必须写明**证据形式**（命令 + 输出摘录，或 `文件:行号`）；不接受「已确认」「检查过了」这类无证据回答；
4. 每条必须写明**合法的「不适用」条件**——连续多轮回答「不适用」的问题，进入 T4/T5 的删除候选流程。

下面 8 条是**种子**，逐条改写成上述格式即可（出处已给，不要替换成别的规则）：

| # | 问题 | 出处 |
| --- | --- | --- |
| 1 | 这次改动里，哪些结论的依据是「系统返回了什么」而不是「契约/决议要求什么」？ | `AGENTS.md` §开发规范（证据诚实）、`docs/audit/CONTRACT.md` |
| 2 | 有没有新增的抽象或机制，找不到一个会变红的检查来钉住它？ | `docs/DECISIONS.md` D22、`scripts/verify_mutation.sh` |
| 3 | 有没有测试写在了**未经用户确认**的缝上？ | `AGENTS.md` §开发规范（TDD 循环纪律）、`CODING_STANDARDS.md` §2 |
| 4 | 有没有 mock 了内部模块，而不是系统边界（LLM/时钟/Redis/讯飞/浏览器音频/IPC）？ | `AGENTS.md` §开发规范（只 mock 系统边界） |
| 5 | 有没有新增「默认关闭、没人跑」的分支或设置？新设置有没有三处同步（`settings/config.py` / `compose.yaml` / `.env.example`）？ | `AGENTS.md` §开发规范（清洁度 / 设置新增） |
| 6 | 有没有引入被决议排除的依赖，或没在提案里说明的新依赖？ | `docs/DECISIONS.md` D04/D17、`AGENTS.md` §开发规范（依赖纪律） |
| 7 | 跨进程可见的缓存或配置缓存，有没有 TTL 或写路径失效？ | `AGENTS.md` §开发规范（缓存） |
| 8 | 用例动过的跨进程共享状态（如场景绑定表），有没有由 fixture 快照还原？ | `AGENTS.md` §开发规范（测试的共享状态自己还原） |

## 一条完整条目长这样（照这个格式写）

```markdown
- **有没有新增「默认关闭、没人跑」的分支或设置？**
  证据：新设置的默认值，以及它在 `compose.yaml` 与 `.env.example` 里的对应行（`文件:行号`）；
  若默认关闭，指出哪一层会真的跑它。
  不适用：本次没有新增分支、也没有新增设置。
  出处：`AGENTS.md` §开发规范（清洁度 / 设置新增）。
```

## 反例（写成这样算不合格）

- 发明既有文档里没有的规则（例：「所有公开函数必须有 docstring」——本仓库没这条）。
- 写成规定而不是问题（例：「供应商调用必须走 ai_resilience 链」→ 那是 `AGENTS.md` §开发规范，不是必答问题）。
- 接受无证据回答（例：「已确认符合规范」）。
- 没有「不适用」出口（会让清单每轮都全文抄一遍，变成新的重流程）。
- 顺手改 §1–§4 的措辞或编号。
