### 1.3 本阶段要做的八件事

1. **必答问题**（C 方案）：把不能自动化的判断类规则改写成评审期逐条必答、且必须带证据的问题。
2. **高风险面清单**：把「人必须看什么」成文——权限与认证 / 状态变化与幂等 / 并发与重试 / 数据一致性与迁移回滚 / 对外契约与降级语义。
3. **意图复述 + 实现决定交代**：票据**开工前**必填「我理解要做什么 / 我打算怎么做 / 我不做什么」（模型自述，**不需用户点头**）；**收工时**必填「spec 未覆盖、我自行拍定了什么」；验收包聚合成一栏，并附改动面（**与声明的写入路径机械比对，越界即红**）与高风险面自查。
4. **跨模型交接格式**：五栏（范围 / 唯一写入路径 / 验收口径 / 红线 / **不接受的自由度**）。
5. **规则复审**（D → A）：先用成本对称性检验筛出删除候选（**只产出清单，不删任何规则**）；再用反向消融测 **§6 必答问题机制本身对弱模型有没有用**——同一任务 A/B 两跑，唯一差别是给不给 §6。
6. **异家族对抗评审**（双轴分派）：Spec 轴派**异家族同级**模型（`dashscope/qwen3.8-flash`），Standards 轴与意图一致性由规划方跑。评审的**唯一任务**是找「意图复述 / spec / 实际 diff」三者的不一致，**不是评价设计好坏**——任务越窄，弱模型越可靠。
7. **票据尺寸上限**：一票一缝、≤ 4 个用例、一个写入路径。返工单位的大小由票据尺寸决定，不由 checkpoint 决定。
8. **§6 的两处加固**（Q8）：三种回答（证据 / 不适用 / **无法取证**，后者必须点名读不到的路径）；第 7、8 条的**适用条件前置**成必答的第一小问，范围不成立即止——防止拿不适用的规则开出假阳性。

## 5. 预估

| 工作包 | 规模 | 说明 |
| --- | --- | --- |
| T1 高风险面 + 必答问题 | M | 纯文档，但每条都要从既有规则改写、不许发明，需逐条找出处 |
| T2 票据与验收包模板 | S | 两处追加 + 把与既有「偏差」栏的边界说清 |
| T3 跨模型交接格式 | S | 一节：五栏 + ≥4 个例子 |
| T4 成本对称性全表检验 | M | 逐条读 AGENTS.md §开发规范 / §贡献指南 + CODING_STANDARDS §1–§4；**只读不写** |
| T5 机制消融 | M | 2–3 条 × A/B 各 1–2 次 flash；最不确定的是「任务怎么埋违规才不泄露 §6」与「隔离上下文怎么证实」 |
| 验收包 | S | 含 var/ 两份清单的摘要抄录 + 三条回归底线的原始输出 |

**最大风险**：① §6 必答问题写多了就变成新的重流程（所以上限 8 条，且每条必须有「不适用」出口）；
② 弱模型执行文档改写时容易「顺手优化」别处（所以每张票都写死：只改指定文件的指定位置，不许重排既有内容）；
③ T4/T5 的结论若指向删除闸门或硬规则，必须**停下来交用户**，不得写进清单当作既成结论；
④ T5 的消融装置若没校准，会产出一批「恒绿」的假证据（`docs/agents/subagents.md` §4 的老毛病）。
