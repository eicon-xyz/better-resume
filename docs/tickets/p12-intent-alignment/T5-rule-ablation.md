# P12-T5 — 机制消融：§6「评审必答问题」对弱模型有没有用

- Status: ready-for-agent
- Blocked by: T1（§6 必须已落地）
- 编排方：**规划方**（本票不由子代理执行）——装置的有效性取决于隔离上下文与 A/B 唯一变量，需要能派隔离会话并判定输出；子代理嵌套派活不可靠
- 被测模型：`opencode-go/deepseek-v4.1-flash`（与日常执行同款）
- 唯一写入路径：`var/rule-audit/ablation.md`

> 阶段：P12（意图对齐与验收减负）。依据 `README.md` §1.4 **Q7**：消融对象由「T4 的删除候选」改为「§6 机制本身」。

## 目标

T4 筛出的 3 条候选是**提醒类**规则（记得跑 ruff / 记得跑契约三件套 / 记得可以开 hooks），
它们的后果本来就能被 CI 机械发现，消融测不出新信息。本票改测**机制**：

> `CODING_STANDARDS.md` §6 的「评审必答问题」对 flash 到底有没有用——**给了它，模型能不能自己抓住自己的违规？**

## 为什么这个对象值得测

§6 是本阶段最主要的交付物，而它的全部价值建立在一个**未经验证的假设**上：
「弱模型记不住规则，但能回答眼前的问题」。如果 B 组（给 §6）与 A 组（不给）犯同样的错，
§6 就是装饰，必须换形态（例如从「记得回答」改成「必须逐条填表并贴证据」）。

## 装置（先校准，再测；否则只是又造一个恒绿的检查）

1. **隔离上下文**：`cd "$(mktemp -d)"` 建 A / B 两个目录，只放任务材料。
   目录里**不能有 `AGENTS.md`、`CODING_STANDARDS.md`、`docs/`**——workspace instructions 会自动注入，规则一旦在场，消融就失效。
2. **隔离证实（校准第一步）**：先问被测模型「你当前能看到哪些项目规范文件？逐条列路径」。
   A 组必须答不出 `AGENTS.md` / `CODING_STANDARDS.md`。**答得出 → 隔离失败 → 停下来报，不要继续**。
3. **A/B 唯一变量**：两组任务文本**逐字相同**，只在 B 组末尾附 §6 的 8 条必答问题原文。任何其它差别都会污染结论。
4. **同款模型**：A、B 都用 `opencode-go/deepseek-v4.1-flash`。换更强的模型测出来的「不会犯错」，测的是那个模型的能力，不是 §6 的价值。
5. **违规必须是真实形态**：埋进任务的违规取自仓库真实发生过的问题（素材：`PROBLEMS.md`、`docs/audit/units/*.json`、`docs/history_docs/`）。
6. **任务文本里不许出现 §6 的问题原文或同义改写**——否则测的是「会不会照做」，不是「会不会犯错」。

## 测哪几条

§6 的 8 条不必全测，挑 **2–3 条**最可能被弱模型违反的。优先顺序：

1. **第 1 条**（结论的依据是「系统返回了什么」还是「契约/决议要求什么」）——本轮实际出现的执行方失误形态最接近它（T1 曾给出一条未实测的理由，见 `PROBLEMS.md` §3）；
2. **第 5 条**（新增「默认关闭、没人跑」的分支或设置；新设置三处同步）；
3. **第 8 条**（用例动过的跨进程共享状态有没有 fixture 快照还原）。

## 判定

| A 组（不给 §6） | B 组（给 §6） | 结论 |
| --- | --- | --- |
| 犯错 | 抓住 | **§6 有效**——机制在挣钱 |
| 犯错 | 也犯错 | **§6 无效**——弱模型读了也拦不住自己，需要换形态 |
| 不犯错 | — | **任务失效**，换任务重跑；不许硬判「§6 有效」 |

## 产出（`var/rule-audit/ablation.md`）

- 隔离校准记录（问了什么、A 组怎么答的）；
- 每条：任务 prompt 原文 / A 组输出摘录 / B 组输出摘录 / 判定 / 各跑了几次；
- 末尾：总调用数。
- **摘要必须抄进 `ACCEPTANCE.md`**（`var/` 不进 git，只引路径等于没有证据）。

## 红线

- 不改任何规则文件、不改代码、不提交（由规划方收口）。
- 临时目录一律 `mktemp -d`，临时脚本一律 `set -euo pipefail`。
- prompt 不泄露 §6；装置未校准不得产出结论。
- A 组不犯错时不许判「§6 有效」——那是任务失效。
