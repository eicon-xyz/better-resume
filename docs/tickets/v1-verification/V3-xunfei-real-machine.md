# V3 — 讯飞 AST 真机验证

- blocking：无（需要 Q4 的三件套 + 一段真实中文语音）
- 纪律：真机失败就写失败原因（凭据缺失/网络/字段不符），不允许"跳过但不说"

## 目标

验证 M4 的讯飞实时转写适配器在真机上成立：HmacSHA1 签名 URL 能握手、1280B/40ms 推流被接受、
`cn.st` 分段能被我方句池归并（apd/py/rpl/尾缀合并）、松手后 final 不丢、错误码有解释。

## 交付物

- `apps/api/scripts/media_smoke.py` 增加 `--xunfei-real --wav PATH [--realtime]`：
  - 读 16k 单声道 PCM/WAV，按 40ms 切片推流（默认加速播放并在日志里标注倍速）
  - 打印：握手 URL（签名部分脱敏）、`cn.st` 原始帧片段、归并后的句子序列、final 结果、错误码
  - 断言：至少 3 句中文文本、无重复整句、`final` 到达、连接关闭码正常
- `docs/tickets/v1-verification/V3-EVIDENCE.md`：原始输出（脱敏）+ 字段映射表（讯飞字段 → 我方模型）
  + 错误码表实测值
- 若凭据拿不到：在 `ACCEPTANCE.md` 写"环境不具备（缺 X），未验证"并保留 `--xunfei-real` 的 dry-run 证据

## 测试与验收

| 用例 | 断言 |
| --- | --- |
| 脚本自测 | MockTransport/脚本自带的假服务端下 `--xunfei-real` 分支可跑通（不需要真凭据） |
| 真机握手 | 101 升级成功；日志时间戳单调 |
| 真机转写 | ≥3 句、句子与音频内容人工核对一致（不一致就写差异） |
| 错误面 | 故意用错 key → 明确错误码 + 可读解释；断网 → 有界重连后失败退出（不无限重连） |
| 成本 | 记录音频时长与调用次数 |

## 不做

- 不做方言/远场/多说话人评测；不做 ASR 质量打分（M4 只承诺链路正确）。

## 预估

1 会话（含 10–20 分钟音频准备）；讯飞按量计费，10 分钟音频量级很小。
